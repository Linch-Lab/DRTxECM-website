Verify the download (optional)

In Command Prompt, run:

certutil -hashfile DRTxECM-win64.zip SHA256

Compare the output with the contents of SHA256SUMS.txt; if they match, the file is intact and unmodified.

Installation

  1. Unzip DRTxECM-win64.zip into any folder (for example C:\Tools\DRTxECM)
  2. Run DRTxECM.exe
  3. The first launch has to unpack and load the libraries, so it is slower than later ones (a few seconds to a dozen or so seconds)
  4. Import your EIS data and you are ready to start; the workflow is described in the Guide

Please unzip the archive completely before running, and do not double-click the executable from inside the ZIP file. Windows' "compressed folder" view prevents the program from correctly reading the libraries stored in the same folder.

Running from source (macOS / Linux)

The packaged portable build is currently available for Windows only. macOS and Linux users can run the program from source, which requires Python 3.10 and a few scientific computing packages: 

git clone https://github.com/Linch-Lab/DRTxECM.git
cd DRTxECM
pip install numpy scipy pandas matplotlib scikit-learn cvxopt PyQt5 click
python launch.py

For complete instructions (including how to download a ZIP instead if you do not have git), see INSTALL.md.

Download troubleshooting

The button did not start a download?

The button links to the file on GitHub Releases. If your network environment blocks GitHub, you can use the Releases page to pick the file manually, or use a proxy.

Windows shows "Unknown publisher" or a SmartScreen warning?

Because this project has not purchased a code-signing certificate. That is common to all free open-source software and does not mean it is a virus. You can click "More info" → "Run anyway"; or build it yourself from source, so that you can be sure the executable matches the code. You can also verify the download with the SHA256 procedure above.

Antivirus software reports a false positive?

Executables packaged with PyInstaller are occasionally misidentified. This project's build pipeline deliberately disables UPX compression (UPX markedly increases false-positive rates). You can verify the SHA256 first, or build from source yourself.

After unzipping, running it reports "xxx.dll not found"?

This usually means it was run without being fully unzipped, or that the extraction was interrupted. Please delete the whole folder and unzip it again.

"Windows cannot access the specified device, path, or file"?

This means Windows blocked the program before it ever started — it is not a fault in the application itself. DRTxECM is not code-signed, so machines managed by a school or an employer may be configured to refuse unsigned executables. Try these in order:

  1. Right-click the ZIP file → Properties → tick "Unblock" → OK, and only then extract. That clears the "downloaded from the internet" mark on every file at once. If you already extracted, select all the files in the folder, right-click, Properties, and tick "Unblock".
  2. Check your antivirus quarantine to see whether DRTxECM.exe was isolated.
  3. Extract to C:\DRTxECM instead — a short path on a local disk that is not cloud-synced. (Windows limits paths to 260 characters; the longest path inside this bundle is 100 characters, so the folder you extract into must stay under about 159.)
  4. If the folder lives in OneDrive, make sure the files are not "online only" placeholders: right-click the folder and choose "Always keep on this device".

Still stuck? The release includes 診斷.cmd — just double-click it. It checks file integrity, path length, the download block (and can remove it), policies that refuse unsigned executables (AppLocker / WDAC), and your antivirus state and detection history. Paste the whole output into GitHub Issues and the cause is usually obvious. The "使用前必讀.txt" (read-me-first) file in the same folder explains all of this in Chinese.

On a school or company computer, the likely cause is an IT policy that only permits signed programs (AppLocker / WDAC). The application cannot work around that; you would need your IT department to allowlist DRTxECM, or use a personal computer. Section [4] of 診斷.cmd reports these policies.
